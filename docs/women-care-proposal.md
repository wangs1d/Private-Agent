# 人文关怀功能方案(第一期:女性安全与生理关怀)

> 状态:提案(待评审) · 日期:2026-09-19
> 目标:在 Private-Agent 中引入"人文关怀"能力域,第一期聚焦女性用户的安全守护与生理周期关怀,兼顾情绪陪伴。

---

## 1. 市面调研:哪些功能真的获得了好评

### 1.1 安全类

| 产品 | 好评功能 | 对我们的启示 |
|---|---|---|
| Noonlight(美国) | 一键触发,接入专业调度员,可通知警察/消防/医疗 | 信任感来自"触发后真的有人/有流程接住";交互必须极简 |
| bSafe | SOS 一键报警 + 实时位置追踪(Live Tracking)、语音激活求救、伪装来电 | "语音/免解锁触发"和"伪装来电"是被反复提及的亮点 |
| 怕怕(国内) | 伴随守护(实时位置共享给守护人)、一键求救(自动录音+发位置)、伪装来电脱身 | 国内用户习惯"守护人"模式,而非专业调度 |
| 滴滴·女性保护 | 行程分享、全程录音保护、一键报警、偏航提醒、夜间人脸核验 | "偏航提醒""到家确认"适合 Agent 主动化 |

**差评/流失点**:GPS 定位延迟、误触、订阅付费墙、更新后不稳定。SOS 类功能的口碑生死线是**可靠与低延迟**,不是功能数量。

### 1.2 生理健康类

| 产品 | 好评功能 | 对我们的启示 |
|---|---|---|
| Flo(全球用户量最大) | 周期/排卵预测、症状记录、个性化见解;获 FDA 许可的经期诊断工具(EDD);Dobbs 判决后推出 Anonymous Mode(匿名模式) | 科学感(FDA/研究背书)+ 隐私承诺是两大信任支柱 |
| Clue | 以科研合作起家,"科学-backed"是品牌心智 | 预测算法要讲清楚边界,不做神神叨叨的断言 |
| Apple 健康·周期跟踪 | 端上加密、手表腕温回溯排卵 | "数据不出设备"本身就是卖点 |
| 美柚/大姨妈 | 经期+备孕+怀孕+育儿多模式切换、智能提醒、社区 | 多人生阶段模式切换是成熟范式;但**社区重运营,第一期不做** |

### 1.3 情绪陪伴类(行业趋势)

- 女性健康产品正从"经期记录工具"走向"全周期陪伴"(Flo、Oura、Garmin 均已覆盖备孕/孕期/更年期)。
- **情绪关怀已成标配**:经期情绪打卡、情绪诱因分析、陪伴式内容(Health & Her、CBNData《被激素硬控的女性》报告均指向此趋势)。

### 1.4 市场教训(翻车点 = 我们的差异化机会)

1. **隐私是最大雷区**:Flo 曾因向 Facebook/Google 共享健康数据与 FTC 和解(2021);多布判决后大量用户删除经期 App,担心数据成为"呈堂证供"(见 [The Bureau of Investigative Journalism](https://www.thebureauinvestigates.com)、[ACM 经期 App 隐私分析](https://dl.acm.org)、[PMC 2025 研究](https://pmc.ncbi.nlm.nih.gov));Flo 的应对是 [Anonymous Mode](https://flo.health)。国内经期 App 也普遍被批评数据采集与广告推送问题(爱范儿《为什么我讨厌"粉粉嫩嫩"的经期记录应用》)。
2. **粉红刻板印象**:说教式关怀("多喝热水"式文案)、把女性身份窄化为"备孕/母婴"会引发反感。
3. **过度承诺**:把周期预测包装成医疗结论、把 SOS 包装成"专业救援"而没有真实链路,都是信任杀手。

> **本项目的天然优势**:私有化部署 + 数据本地化(直击隐私痛点)、proactivity 主动服务管道(别家要用户打开 App,我们的 Agent 会主动问候/告警)、自然语言交互("我刚到家了"即可打卡)、全链路执行(打电话、定位、浏览器代操作)。

## 2. 产品定位:做什么,不做什么

**做**:
- 隐私优先的生理周期记录/预测/轻提醒(数据默认加密落本地,不出本机服务器)
- 面向真实链路的应急与守护:紧急联系人通知、守护模式(位置+到家确认+超时升级)、设备级一键报警
- 情绪与症状的自然语言陪伴式记录,联动已有健康模块
- 就医辅助:症状整理、陪诊摘要、代挂号(复用共享浏览器)

**不做(第一期)**:
- 不做专业调度救援(无 Noonlight 式调度接入资质,SOS 走设备拨号 + 紧急联系人,并在文案中明确"不替代报警")
- 不做社区/内容平台(重运营、审核风险高)
- 不做医疗诊断与生育力断言;不做月经"羞耻化/神秘化"包装

## 3. 功能方案

### A. 安全守护(safety-guard)

**A1 紧急求助 SOS(P0)**
- 触发(≤2 步):移动端聊天页快捷卡/通知栏快捷按钮/悬浮球长按 → 3 秒倒计时可撤销(防误触,行业通行做法)。
- 触发后动作(并行):设备端唤起拨号盘(110/120/119 预填,由用户按下拨号,合规且真实可用)→ 服务端向紧急联系人发送短信/推送(含实时位置 + 预设求助文案)→ 可选自动录音留证 → 桌面端弹窗提示"求助已发起"。
- 求助后 Agent 主动跟进:"需要我继续把位置发给第二位联系人吗?""到你说的咖啡馆还有 400 米。"

**A2 夜归守护模式(P1,本产品独有的主动化场景)**
- 出发前说"今晚加班,11 点到家,帮我开着守护"→ Agent 建立 30/60/120 分钟级守护任务:持续定位 + 预计路线时间。
- 到达时间点主动确认("到家了吗?"),用户回复或到达地理围栏即打卡;**超时未确认 → 走 proactivity 升级链**(弹窗 → TTS 语音询问 → 自动外呼用户本人 → 仍无响应则通知紧急联系人)。
- 行程偏航/长时间静止等异常可作为 M2+ 的增强项(依赖连续定位质量,谨慎承诺)。

**A3 借口脱身(P1)**
- "帮我找个借口离开"→ 两个实现:a) **真实来电脱身**:用现有 phone-call 能力外呼用户手机,来电显示"小助手",接通后播放预设借口话术(本产品独有:别家只能伪装界面,我们是真来电);b) 生成脱身话术/定时消息(微信代发可走后续能力)。

**A4 安全档案(P0,配置面)**
- 紧急联系人(1~3 位,含通知偏好与一句话授权说明)、医疗要点(血型、过敏史、慢病,供急救时口述)、可信地点(家/公司围栏,供守护模式判定"到家")。
- 入口藏在设置内,**默认不主动展示**,避免"女性=需要被保护"的预设感。

### B. 生理周期关怀(period-care)

**B1 记录与预测(P0)**
- 自然语言记录:"今天早上来月经了""这次 5 天结束,第二天量很大"→ 结构化落库(起止日、流量、痛经程度、症状标签)。
- 预测:M1 用滚动统计(近 3~6 个周期的中位数 ± 离散度),随数据积累收窄;明确标注"估算,非医学结论"。
- 呈现:聊天内周期日历卡片(新增 `[RENDER_AS:cycle_calendar]` 渲染路由),桌面/移动端共用。

**B2 轻提醒与关怀语(P0)**
- 经期临近提醒(可配置提前 1~3 天)、痛经高发日的"今天要备着暖宝宝吗"式提醒。
- 文案基调:**给选项不给指令,不说教**;称呼走已有的用户理解档案(称呼、语气偏好);提醒错过不追问、不制造焦虑。
- **通知脱敏**:所有提醒在系统通知栏显示为中性文案(如"小助手有一条提醒"),点开才见详情——锁屏可见性是经期 App 的经典隐私痛点。

**B3 症状/情绪联动(P1)**
- 经期问一句"今天状态怎么样?"→ 情绪/睡眠/疼痛记录进既有 health-fitness 指标体系,跨周期做相关性提示("近三个月经期前两天你的情绪评分都偏低")。
- 客户端已有情绪球(emotion ball)资产,可作为情绪记录的轻交互入口。

**B4 异常温和提示(P1)**
- 连续 >60 天无记录、单次经期 >10 天、痛经评分持续走高 → 温和提示"这个情况和平时不太一样,要我把最近的记录整理成一份可以带给医生的摘要吗?"(转就医准备,不下诊断)。

**B5 人生阶段模式(P2)**
- 经期 / 备孕 / 孕期 / 产后 / 更年期模式切换(美柚验证过的成熟范式),切换后调整预测模型与提醒策略;第一期只预留字段,不实现。

### C. 情绪与就医辅助

- **C1 情绪打卡与诱因回看(P1)**:低摩擦打卡(一句话/选表情),周报里给"情绪日历";绝不主动做心理评估或危机干预角色,遇到明显危机信号时仅提供正规援助渠道信息(热线等)。
- **C2 就医准备(P2)**:把症状记录整理为结构化"就诊摘要"(时间线+主诉+既往记录),Agent 可通过共享浏览器代挂号(现有 shared-browser 能力)。

### D. 隐私即关怀(贯穿所有功能,不是附加项)

1. **加密底座**:周期、情绪、位置、紧急联系人等敏感数据一律 AES-256-GCM 加密落盘(复用 `browser-session-crypto.ts` 模式;现状 agentic-memory 为明文,本方案数据不入明文库)。
2. **本地优先**:周期/情绪数据不离开本机服务端;位置仅在守护模式激活期间采集,任务结束即停,历史位置可一键清除(`purgeActor` 钩子已有)。
3. **通知脱敏**:见 B2;桌面通知窗与移动推送同样适用。
4. **一键隐身/清除**:设置内提供"清除全部关怀数据"按钮,无需理由,立即生效。
5. **合规红线**:经期/位置属《个人信息保护法》敏感个人信息,首次启用需单独、明示同意;未成年人默认关闭守护模式的持续定位;所有预测文案附"非医疗建议";SOS 文案附"不替代拨打报警/急救电话"。

## 4. 技术落地方案(映射现有架构)

扩展点结论来自对现有代码的梳理(`docs/PROJECT_MAP.md` 的"新功能加哪里"原则:tools 薄、services 厚):

| 功能 | 服务端 | 客户端 |
|---|---|---|
| 模块注册 | 新建 `server/src/tools/capability-modules/period-care/` 与 `safety-guard/` 各四件套(chat-tools/handlers/intent/index),在 `capability-modules/index.ts` 的 `buildCapabilityModules()` 注册 | — |
| 业务逻辑 | `server/src/services/period-care-service.ts`、`safety-guard-service.ts`,在 `bootstrap/create-app-services.ts` 注入依赖 | — |
| 数据存储 | 周期/情绪入 `agentic-memory/structured-fact-store.ts`(actor+field KV,天然适合周期字段);守护任务/联系人入独立 SQLite 表;**统一 AES-256-GCM 加密** | — |
| 意图路由 | 两个模块自带 INTENT_RULES(BM25 调权),"月经/例假/痛经"→ period-care,"救命/害怕/跟踪"→ safety-guard(高优先级直通) | — |
| 主动提醒/升级链 | 复用 `server/src/proactivity/` 管道:周期提醒 = 提示级;守护超时 = critical 级(popup→TTS→外呼→通知紧急联系人) | Windows 自绘通知窗(确认/稍后按钮回调已有)、Android 系统推送(MobilePushPlugin) |
| 富卡片 | 周期日历卡新增 `[RENDER_AS:cycle_calendar]` 路由;SOS 状态卡、守护模式卡走 replyBlocks `card` 块 | `message_body_renderer.dart` 扩展路由;卡片动作经 `onUserAction` 回传 |
| 定位 | `location-env.ts` 已定义 ondemand/continuous 模式 + 地理围栏,守护模式用 continuous | Android `LocationHelper.kt` + 已声明的后台定位权限;Flutter `geolocator` |
| 外呼/短信 | `phone-call` capability module(借口来电、守护升级外呼);紧急联系人短信走 email-sms 模块 | Android 设备级拨号(Intent.ACTION_DIAL 预填 110/120,由用户确认拨出) |
| 健康面板(M3) | 服务端渲染 `/wellness` 页面(周期日历、症状时间线),复刻 `/travel-map` 模式 | 复刻 `travel_web_panel_host.dart` 单例 WebView 宿主,挂 right_side_panel |
| 代挂号(M3) | shared-browser 工具链 | 确认门走 approvals 面板范式 |

**SOS 关键交互必须在端上完成**(网络/服务端不可用时也要能拨号):移动端本地实现触发器(通知快捷按钮、悬浮球长按),服务端不可达时降级为纯设备行为(拨号盘 + 本地短信)。

## 5. 分期计划

| 里程碑 | 内容 | 预估 |
|---|---|---|
| **M1(可用)** | period-care:记录/预测/轻提醒/日历卡;安全档案+紧急联系人;SOS(移动端触发+拨号+短信通知);**加密底座与通知脱敏** | ~2 周 |
| **M2(完整)** | 夜归守护模式(continuous 定位+到家确认+超时升级链);借口来电;情绪打卡与症状联动;异常温和提示 | ~2–3 周 |
| **M3(延展)** | Wellness 面板;就诊摘要+代挂号;人生阶段模式字段;知识问答(带来源引用) | 按需 |
| **远期** | 穿戴设备接入(心率/睡眠辅助经期预测);关怀能力泛化到老人(跌倒/用药提醒)、全家场景 | 展望 |

## 6. 风险与开放问题

1. **SOS 可靠性**:定位延迟是行业差评重灾区;M1 先做"最后已知位置 + 短信兜底",持续定位在守护模式内才承诺。
2. **外呼链路依赖**:借口来电/守护升级依赖 phone-call 通道可用性;需评估该通道的号码资质与成本。
3. **预测准确度冷启动**:周期数据 <3 个周期时只记录不建议,避免错误预测伤信任。
4. **情感边界**:陪伴语气需要统一的文案规范(见 B2 基调),建议落一份 `docs/wellness-tone-guide.md` 供 prompt 与通知模板共用。
5. **范围控制**:第一期克制,先让"记录—提醒—求助"三条链路真实可靠,再谈扩展。

# Agent 桌面操控能力对齐主流(Anthropic Computer Use / OpenAI CUA / UI-TARS)

## 现状与差距(已核实)

项目已有 `desktop-visual/` Python 桥 + `server/src/tools/desktop-visual-tools.ts` 的 11 个 `desktop.*` 工具(截图/UIA 查询与操作/键鼠/shell/预设/桌面联网/VLM 视觉循环)。与主流 agent 对比的实测差距:

1. **【P0·真 bug】桥接断路**:`bridge_ws_client.py` 只映射 screenshot/open/uia_query/run_shell/run_task 五个 action;server 端 `desktop.run_automation`/`http_get`/`web_search`/`web_fetch` 走桥接时会被误判成 run_task(task 为空)**必然失败**;`desktop.run_input`(键鼠)在 server 端被硬编码为仅限服务器本机 → **手机远控电脑时无法操作键鼠**。
2. **【P1】输入动作空间缺**:无 wait/triple_click/横向滚动/滚动目标坐标/cursor_position/长按;`type` 用 `pyautogui.write` **打不了中文**(但工具描述声称支持);按键白名单过窄。
3. **【P1】观察能力缺**:仅主显示器、无截图降采样与坐标标定(scale)、DPI 感知不统一(缩放屏上截图物理像素 vs 光标逻辑像素错位风险)。
4. **【P1】窗口管理/剪贴板缺失**(主流桌面 agent 标配):无法列窗口/激活/关闭窗口,无法读写剪贴板。
5. **【P1】UIA 短板**:run_automation 缺 select/expand/collapse/scroll_into_view;query 无法限定目标窗口;缺整树 snapshot 模式(主流"快照→按元素操作"模式)。
6. **【P2】run_task 步骤不流式**:`visual_loop` 有 `on_step` 钩子但未接到 `desktop.event` 通道,长任务 10 分钟无反馈。
7. **【P2】schema/文档/验证脚本滞后**(`desktop-visual/tests/` 为空)。

## 改动清单

### A. Python 桥接端(desktop-visual/desktop_visual/)

1. **`bridge_ws_client.py`(P0)**:显式新增 action 映射 run_input / run_automation / http_get / web_search / web_fetch / show_message / window / clipboard → stdio_worker,消除"掉默认分支被当 run_task"的必败路径。
2. **`stdio_worker.py`(P1)**:
   - `_handle_run_input` 扩展:新增 `wait`、`triple_click`、`cursor_position`、`hold_key`;`scroll` 支持可选目标 (x,y) + 横向滚动;`type` 对含非 ASCII 文本自动走"剪贴板备份 → Ctrl+V 粘贴 → 恢复剪贴板"路径(修复中文输入),ASCII 仍走逐字;VALID_KEYS 放开为 pyautogui 全键集。
   - 新增 `_handle_window`:list / activate / close / minimize / maximize / move / resize(ctypes EnumWindows,激活逻辑从 `_launch_and_verify_window` 抽成公共函数复用)。
   - 新增 `_handle_clipboard`:get / set(CF_UNICODETEXT,ctypes 实现,不加新依赖)。
   - `run_automation` 增加 select / expand / collapse / scroll_into_view(SelectionItem 10010 / ExpandCollapse 10005 pattern),selector 支持 `window_title` 限定顶层窗口。
   - `uia_query` 增加 `mode=snapshot`(前台/指定窗口控件树,深度与数量上限,元素带编号+bbox,供模型按名引用)。
   - `_handle_screenshot`:支持 `display`(多屏,PIL ImageGrab all_screens)与 `maxDim`(降采样),返回 `scale/screenWidth/screenHeight`。
   - worker 启动时设置 Per-Monitor v2 DPI aware,全链路统一"屏幕物理像素"坐标系。
3. **`mouse_controller.py` / `capture.py`(P1)**:triple_click、横向滚动、scroll_at(x,y)、mouse_down/up、hold_key;多屏抓取 + 降采样工具函数。
4. **`visual_loop.py`(P1/P2)**:LoopConfig 增加 `max_screenshot_dim`;`on_step` 保持,P2 增加步骤事件输出管道。

### B. Server 端(server/src/)

5. **`services/desktop-visual-port.ts`**:port 类型扩展(window/clipboard/screenshot 的 display+maxDim/uia snapshot/run_input 新 action/新 automation action)。
6. **`services/desktop-visual-subprocess.ts`**:payload 透传新 action(该实现是 spawn stdio_worker 的通用管道,预计只需类型同步)。
7. **`tools/desktop-visual-tools.ts`(P0+P1)**:
   - `desktop.run_input` 去掉"仅 localVisual"限制,改为 bridge 优先、localVisual 兜底(P0 核心修复)。
   - 新注册 `desktop.window`、`desktop.clipboard`(审计记录 + bridge/localVisual 双路径,与现有工具一致)。
   - `desktop.visual.screenshot` 透传 display/maxDim。
8. **`tools/desktop-visual-chat-tools.ts`(P1)**:更新 run_input/uia_query/run_automation/screenshot 的 schema 与描述(写明坐标系=屏幕物理像素、image 坐标换算字段、新 action 列表);新增 DESKTOP_WINDOW_TOOL / DESKTOP_CLIPBOARD_TOOL 定义。
9. **`external-model/resolve-chat-tools.ts`(P1)**:`DESKTOP_VISUAL_PINNED_TOOLS` 增加 desktop.window / desktop.clipboard。
10. **`services/desktop-bridge-coordinator.ts`(P2)**:转发 `desktop.task.step` 事件(复用现有 desktop.event 订阅通道,Py 端 run_task 每 步经桥接推送),供客户端实时展示操作步骤;客户端 UI 渲染可作后续项。

### C. 测试与文档

11. **`desktop-visual/tests/`**:为 parse_action_json / validate_action_output / 新 action 参数校验 / run_automation selector 解析添加 pytest(纯逻辑,不依赖真实桌面)。
12. **`server/scripts/verify-desktop-control.ts`**:仿 verify-rollinggo-mcp.ts,DESKTOP_VISUAL_STUB=1 下走 ToolRegistry 对全部 desktop.* 工具做参数校验级冒烟。
13. **`docs/desktop-control.md`**:工具地图、坐标系约定、环境开关、安全护栏;README 中 desktop-visual 段落同步。

## 关键设计决策

- **坐标系**:全链路统一"屏幕物理像素";截图降采样时返回 scale,模型用截图坐标操作时传 imageWidth/imageHeight 由 Python 自动换算。
- **中文输入**:剪贴板暂存→粘贴→恢复,粘贴失败回退逐字输入。
- **新工具暴露策略**:沿用现有 pinned 机制(仅 Complex/delegate/full 访问模式或桥接在线时进 LLM 视野),不给 Fast 模式加 token 负担。
- **零新增第三方依赖**:窗口/剪贴板全部 ctypes,截图用已有 Pillow。

## 实施顺序

P0 桥接修复 → P1 动作空间/观察/窗口/剪贴板/UIA → P2 步骤流式 + 测试文档。每阶段可独立提交、独立验证。
